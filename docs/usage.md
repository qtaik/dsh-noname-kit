## 安装、更新与卸载

桌面版在「插件」面板安装、更新或卸载 `dsh-noname-kit`。也可完全退出桌面版后，使用其自带命令行安装指定版本：

```powershell
& "D:\Apps\DSH\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add "dsh-noname-kit@<版本号>"
```

把示例路径换成实际桌面安装目录，并填入要安装的版本。`--profile desktop` 对应桌面配置，`--profile web` 对应独立的 Web 配置，两者不会互相安装插件。

Web 版可用 `dsh plugin --profile web add dsh-noname-kit` 安装，也可将包名替换为 GitHub 仓库地址 `https://github.com/qtaik/dsh-noname-kit.git`。安装或更新后重启 DSH，新建会话选择「无名杀开发模式」。

工坊「设置 → 版本与一致性」显示当前版本和升级命令，只提示更新，不自动安装。启动时的版本检查可以关闭；联网失败不影响其他功能。以源码链接方式加载的插件不参与版本检查。

DSH 0.1.7 起随插件加载开发模式。0.1.6 及以下的宿主使用独立副本，可在设置页点「重装 preset」，或在插件目录运行 `node scripts/install-preset.mjs`；覆盖前会备份，重装后对新建会话生效。开发模式使用原生工具调用，不随宿主的全局 PTC 设置改变。

插件的 Node.js 要求见 [package.json](../package.json)，同时须满足所用 DSH 的要求；例如 DSH 0.2.2-rc.1 要求 Node.js 24.9.0 及以上。桌面版自带运行时，Windows 下的 Bash 工具使用本机 Git Bash，工具权限由宿主设置决定。

Web 版卸载命令为 `dsh plugin --profile web remove dsh-noname-kit`。卸载插件不会删除游戏里的「联机助手」内核、扩展、任务、历史或备份；不再使用内核时，可在游戏的扩展菜单中删除。

## 游戏目录与设置

从输入框旁的「🛠 工坊 → 设置」配置游戏目录；Web 版先启动 `dsh web`。选择游戏本体层，常见结构中可同时看到 `extension/` 与 `noname.js` 或 `noname/` 等引擎内容，例如 `D:\Games\Noname\resources\app`，部分安装结构在 `resources/app/src`。不要选择 `extension/` 中的某个包。

自动扫描只提供候选，选中并保存后才会使用。以设置页校验结果和「当前」路径为准；切换目录不会搬移扩展，也不会改写旧任务和会话记录的目标路径。

启动时按以下顺序选择目录：

1. 当前 Profile 中有效的插件行配置 `nonameDir`（`cordis.yml` 或 `cordis.patch.yml`）。
2. 工坊保存的有效目录。
3. 仅生成模式。

工坊保存后会立即切换当前进程的目录，但重启时仍优先使用有效的行配置。若重启后路径变回旧值，先检查行配置。工坊设置保存在 DSH 用户目录的 `noname-kit.json`，默认是 `~/.dsh/noname-kit.json`。

没有有效游戏目录时，可以讨论或生成供自行保存的代码；工坊任务登记、扩展读写和素材复制仍需配置目录。「手动复制」只控制源码是否写入，任务记录、准备目录、素材复制、建立索引、内核安装或恢复等操作仍可能写入文件。只想讨论或生成代码时，应在需求中说明。

「AI 单次命令输出上限」默认 64K，可设为 64–256K，对新建会话生效。该项分别限制 Windows 开发模式下 Git Bash 的标准输出和错误输出；其他工具使用宿主限制。

## 开发与任务

新建会话选择「无名杀开发模式」，初始化结束后再提交需求。普通会话的工具发现方式由宿主决定，开发模式会加载配套工具和开发规范。

创建任务时选择新建或编辑已有包，填写目标包、条目和技能描述。武将、卡牌可按游戏版本选择 `game.import` 或 ES Module 写法；「新玩法」使用新版模式结构，交付后从游戏主菜单进入。

创建武将时可勾选「创建新势力」，填写势力名称和势力图片的本地完整路径；勾选「使用视频作为动态立绘」后填写视频路径，支持 MP4、WebM、M4V、MOV、OGV。两项都支持在已有包中新增武将；编辑已有武将也可单独添加或更换视频动态立绘，无需另填技能改动。取消勾选后不提交对应要求，不会删除原有视频或关闭已有动效。静态立绘仍可单独填写，用于视频无法播放时显示；AI 会一并收到这些需求并处理素材与实现。

AI 会先给出需求理解和待确认问题。确认单符合预期后回复「确认」；回答澄清问题只用于消除歧义。实现完成后，自动模式写入源码，手动模式返回成品供保存。较长成品按工具提示继续读取，避免只保存了第一页。

进游戏测试每个技能或规则，再在任务列表逐项确认；有问题点「反馈」，附上实际现象和完整报错。新建武将、卡牌任务还需图片就位，登记过的配音也须交付齐；新玩法不强制补图，编辑已有条目的任务不强制补图。满足这些条件后自动归档，手动标记完成前也应核对未测项目和缺失素材。

### 编辑已有扩展

选择「编辑已有扩展包」，先核对包名、条目 ID 和所在文件。勾选需修改的技能并分别描述变化；武将体力、护甲、名称等填在条目的改动描述里。编辑模式包时，直接描述模式骨架和规则的变化。

「建立区块索引」会先备份，再给能安全定位的条目插入锚点注释，必要时补末尾逗号；多文件包在实际定义条目的文件中处理。索引可以只完成一部分：重名、非连续翻译、只读或无法唯一定位的定义保留原文，结果会列出未索引项。

多文件同名条目要选定实际文件，同文件重复定义不能猜选。没有唯一索引时，AI 应先读取原文，再用唯一命中的文本替换；全文覆盖仍会检查改动范围和范围外内容。运行时逐项赋值（如 `pack.skill.xxx = {}`）没有可供锚定的对象条目，不能按这种方式建索引。

源码覆盖前会自动备份，历史页可查看扩展和备份。任务完成仍以实际游戏测试结果为准。

## 图片、配音与视频

提供可访问的本地绝对路径，由专用工具复制素材。下表目标均相对于 `extension/<包名>/`；复制文件不会自动补齐技能或条目中的素材引用。

| 素材 | 目标位置 | 同名文件处理 |
|---|---|---|
| 图片 | `image/<纯文件名>`，支持 jpg/jpeg/png/gif/webp | 直接覆盖，不自动备份 |
| 技能配音 | `audio/skill/<技能ID>1.mp3`、`<技能ID>2.mp3`… | 直接覆盖，不自动备份 |
| 阵亡配音 | `audio/die/<武将ID>.mp3`，多句命名按当前引擎约定 | 直接覆盖，不自动备份 |
| 视频 | `video/<纯文件名>`，支持 mp4/webm/m4v/mov/ogv | 默认不覆盖；允许覆盖时先备份到 `backup/video/`，再原子替换 |

图片复制时带任务 ID 才会登记到任务，任务列表「补图」也会完成复制和登记。配音复制时带任务 ID，技能配音另传所属技能名；视频不会登记为图片或配音，也不影响任务自动完成。

武将图片放进 `image/` 后，定义中需显式引用 `img: "extension/<包名>/image/<文件名>"`；卡图按当前引擎配置 `image` 和 `fullimage: true`。新增自带技能配音可使用 `audio: "ext:<包名>/audio/skill:2"`，句数须与文件一致。已有音频引用能否复用、阵亡音频如何命名，应核对当前引擎并实测。素材放在扩展内，不写入游戏本体的图片或音频目录。

视频复制要求扩展包已存在，源与目标后缀一致。目标名不超过 200 个字符，只允许中文、字母、数字、下划线或连字符加支持的后缀，不含空格或子目录。例如：

```json
{
  "folder": "my_pack",
  "videos": [{ "source": "D:/Media/intro.mp4", "target": "intro.mp4" }]
}
```

需要覆盖时，在同一级参数中加 `"overwrite": true`。结果分别列出成功项、备份和逐项错误，部分成功时只需核对失败项。

视频备份保留原后缀，返回的 `backups.path` 相对于扩展包。恢复时，将它按当前游戏目录的 `extension/<包名>/` 解析为绝对路径，作为同一工具的 `source`，将目标设回原文件名并传入 `overwrite: true`；恢复覆盖前也会备份当前视频。

首次创建视频文件要求目标文件系统支持硬链接；不支持的磁盘或共享目录、权限限制可能导致复制失败。工具不转码，复制成功仍须验证游戏和视频编码是否支持播放。

## 联机

联机助手面向官方版无名杀，建议双方使用相同游戏版本和最新内核。新版补传支持 Windows 上的官方 1.11.5.2 / 1.11.6，旧协议不会自动降级补传。

### 建房与连续对局

1. 双方在工坊「联机」页安装或升级游戏内核，在游戏扩展菜单启用「联机助手」，完整退出并重启游戏。
2. 房主点「创建 P2P 房间」获取 6 位房号，朋友输入房号加入。公共信令不可用时，改用「邀请码建房」，朋友把回执码发回房主；邀请码连接不经过公共 MQTT 信令，仍取决于双方网络条件。
3. 在插件房间检查扩展差异，按需补齐文件，再由房主选择模式并载入游戏，客人跟随入座。人满后加入的玩家会排队。
4. 结算后点「返回插件房间」。双方完成本局确认后关闭本局窗口，保留原连接；房主可调整模式并再次载入。

已有房间也可生成邀请码；邀请码房间可以稍后启用房号，发布失败会保留原有邀请和连接。局中解散大厅只关闭入口及未入局连接，当前对局仍可正常结算并返回原连接的插件房间。

开启房间设置中的自由选将后，可按势力、武将包及名称或 ID 查找；候选仍受本局启用包和禁将规则限制。点将单挑和对决 2v2 的队友推荐保留原生布局。

内核显示绑定到另一 DSH，或绑定缺失、失效时，可点「绑定到此 DSH」，随后完整退出并重启无名杀。

### 包体检与补传

包体检比较当前连接的扩展文件，缺包和同名文件差异可形成补传请求。旧连接的迟到结果不会算作本次检查；无法关联的结果显示「本次尚未核验」，需升级内核或重新连接后再检查。

- **接收与重启**：客机对每批请求同意后才接收，整批校验通过再提交并保存启用设置。补传前关闭本目录的对局窗口；完成后客机须完整退出并重启无名杀，Ctrl+R 不等同于重启。若提示自动启用未确认，检查并手动启用所列扩展后重启，无需重新下载。
- **关闭自动补传**：在包体检卡中关闭，本机选择会保存，双方分别设置。关闭会停止尚未提交的批次并拒绝新请求，手动体检仍可用；可自行安装相同扩展并重启游戏。已提交、结果待确认或需要恢复的批次仍须按提示处理，开关不会跳过恢复。
- **重新传输**：房主可对客机重新申请，多人串行处理，每批仍要重新体检并获得客机同意。中断后重传整批文件，不提供断点续传；需要恢复或确认提交结果时先完成该步骤。
- **进度**：100% 仅表示文件接收阶段结束，还需等待整批校验、提交、启用和重启提示。房主显示客机确认接收的字节，客机显示接收到暂存区的字节，多人总览按客机分别显示。
- **容量**：每批最多 64 个扩展、4096 个文件，硬上限 1 GiB。本机默认 300 MiB，可在包体检卡设为 1–1024 MiB，批次须同时符合双方限额。内核在线且没有补传、授权或恢复进行时才能修改容量，旧的较低限额不会自动调高。
- **时限**：按批次大小决定，从请求发出起计算，包含客机确认等待，最长 15 分钟。进度更新、重复消息或修改容量不会延长当前批次的时限。

内置内容及文件一致、仅未启用的扩展不会补传。文件由双方自行复制后仍需完整重启游戏，避免旧代码留在运行中的窗口里。

## 工具与参考资料

| 工具 | 用途 |
|---|---|
| `noname_search_reference` | 搜索本地游戏中的技能、武将和卡牌参考实现 |
| `noname_list_catalog` / `noname_read_catalog` | 列出或读取官方内容与安装扩展，显示来源和解析缺口 |
| `noname_read_extension` | 读取扩展当前源码或分块内容 |
| `noname_validate` | 检查语法和静态规则，不执行扩展代码 |
| `noname_write_extension` | 校验后写入源码，覆盖前备份 |
| `noname_skills_written` | 将任务条目标记为已写入、待测试 |
| `noname_copy_images` / `noname_copy_audio` / `noname_copy_videos` | 复制本地图片、配音或视频 |

搜索参考实现不能代替核对引擎 API。需要教程时，把可访问的文件路径、链接或相关章节交给 AI 按需读取；插件不会自动索引整套外部教程。具体开发要求见 [AI 开发规范](../presets/noname-dev/skills/noname-extension-dev/SKILL.md)和[开发主题指南](../presets/noname-dev/skills/noname-extension-dev/references/development-guide.md)。

搜索、目录与长源码都有分页和各自的资源上限，应按结果给出的游标或偏移继续读取；未搜完、解析失败或没有命中不等于内容不存在。参考搜索可对最大 5 GiB 的单文件分块检索，这不是全文读取或静态解析的上限。手动成品可按 `draftId` 续读，闲置 15 分钟后过期，不会写入游戏文件。

## 反馈与排障

开发任务优先用任务列表「反馈」；插件问题可提 [issue](https://github.com/qtaik/dsh-noname-kit/issues)。先记录问题发生的阶段：

| 现象 | 需要记录的内容 |
|---|---|
| 等待载入、确认或校验 | 双方显示的阶段、最后变化时间、完整提示和待确认按钮 |
| 提交结果待确认、需要恢复 | 当前提示与批次记录；先核对或恢复，不用反复重传代替恢复 |
| 断线或内核离线 | 哪一端先掉线、窗口是否还在、DSH 和内核各自的状态、之前的操作 |
| 窗口退出或无响应 | 发生时间、最后画面、完整报错与堆栈；仅显示离线不能判断为闪退 |

一并提供 DSH、插件、内核和游戏版本，房主或客机身份，设置页当前目录、目标扩展/条目、写入方式，以及最短复现步骤、预期和实际结果。不要先清空存档或缓存、删除恢复文件、反复重传或重装来替代定位。公开日志前遮住 API Key、token、邀请码和回执码。
