# 自定义机制参考

自定义机制用于复用一类技能或规则，不必新建独立游戏模式。先区分技能类型（如“XX技”）、共用规则、全局规则，再按主规范逐项确认需求。优先查同类官方实现；没有完整同款时，把效果拆开查当前引擎的定义与调用点，组合原生事件和 API，仅为缺少的部分补扩展逻辑。保留参考来源和必要兼容方案，不因改用机制对象就重写无关技能。

## 包内接口与接入

在实际扩展 JS 文件中定义 `const nnkMechanic_<id> = { ... }`，对象包含字符串字段 `id`、`name`、`kind`、`description` 和下表中对应的一个公开方法。`id` 须符合 `[a-z][a-z0-9_]{0,63}`，使用包前缀防撞，变量后缀与 `id` 完全一致；例如 `id: 'my_pack_echo'` 对应 `nnkMechanic_my_pack_echo`。显示名和规则说明分别放在 `name`、`description`，不能以另一个机制的同名覆盖代替复用。

| kind | 对应公开方法 | 实际职责与接入 |
| --- | --- | --- |
| `skill-type` | `createSkill(skill, options)` | 按该类型的规则组合传入技能与选项，返回完整的引擎技能定义，由调用方登记到技能表。保留原技能所需的触发、选择、代价、效果、AI及异步执行语义。 |
| `shared-rule` | `resolve(context, options)` | 执行共用结算，明确所需上下文、选项与结果。若为 async 或返回引擎事件，由调用者按当前引擎约定等待完成，再继续后续效果。 |
| `global-rule` | `install()` | 由扩展初始化阶段显式调用，安装已确认范围内的全局规则；处理重复调用、失败和退出/停用清理。仅声明对象不会自动启用规则。 |

对应方法是实际规则的入口，不能仅返回未加工的输入、空对象或展示标签来声称已实现机制。辅助逻辑按需放在同文件或包内模块，不另外创造自动注册协议或专用工具。

ES Module 可写 `export const nnkMechanic_<id> = ...`，由实际使用文件导入；传统 `game.import` 工厂内保留同样对象，在需要的位置调用，保持原有载入方式。多文件包须接通实际导入、技能生成或初始化调用，不能只放一个未被加载的文件。需要解释机制词条时，先核对目标引擎及启用 UI；支持原生 poptip 时复用其入口，不把特定版本的接口当成通用保证。

## 工坊字段与案例

| 字段 | 填写内容 |
| --- | --- |
| 调用时机 | 什么时候由谁调用。技能的准备阶段、主技能步骤、全局规则要监听的事件，都在这里说明。 |
| 判定与结算 | 调用后检查哪些条件，以什么顺序支付代价、尝试执行分支或改变状态，以及取消时怎么处理。 |
| 规则说明 | 给玩家看的规则文字，对应机制对象的 `description`，需与实际结算一致。 |

技能类型还可声明每个技能能调整的参数。全局规则另写启用条件、对象范围和结束条件。**启用条件**决定哪一局或哪个阶段开此规则，**调用时机**决定规则启用后何时结算。

### 技能类型 · 预约技

- **调用时机**　每轮开始时，当前持有者从此技能提供的候选触发时机中选一个，本轮使用所选时机。下一轮重新选择。
- **判定与结算**　候选时机出现时，核对技能仍有效，且该时机是该角色为此技能在本轮选定的时机。符合时，按该技能自身的条件、次数限制和代价判断能否发动，再依该技能的规则结算效果。
- **规则说明**　每轮开始时，你为此技能选择一个本轮的触发时机。到达所选时机时，按此技能的条件判定并结算。
- **技能可调参数**　各技能提供自己的候选触发时机，并定义具体的发动条件、次数、代价和效果。

示例 ID 为 `demo_reserve`。用 `createSkill(skill, options)` 组合技能定义和候选时机，将返回的定义登记到原生技能表。在 1.11.6 中，让技能通过 `trigger: { global: "roundStart" }` 监听轮首事件，使每位持有者分别选择。`trigger.player` 只匹配事件所绑定的角色。按当前持有者、技能 ID 和轮次记录选择，统一处理该技能的候选事件，并核对本轮所选时机。技能被夺取后，原选择仍归原持有者。无候选时如何处理、所选时机被跳过时如何处理，以及中途取得技能是否能在本轮使用，按具体技能需求确定。

**使用例**　同一个预约技能提供两个候选时机，自己的准备阶段开始和自己的结束阶段开始。持有者在每轮开始时选其中一个。1.11.6 对应 `phaseZhunbeiBegin` 和 `phaseJieshuBegin`，在所选阶段到来时才检查该技能的条件及代价。

### 共用规则 · 接力

- **调用时机**　主技能对一名角色的效果结算完毕后，由该角色发起接力。
- **判定与结算**　由受到主技能效果的角色选择另一名符合该技能条件的在场角色。没有合法目标、选择者离场或取消时，结束接力。选定后，仅对接棒者结算一次主技能传入的效果，例如摸一张牌或获得 1 点护甲。接力效果结算完毕后直接结束。
- **规则说明**　此技能对一名角色的效果结算后，该角色可选择另一名符合条件的在场角色，令其获得此技能规定的一次接力效果。

示例 ID 为 `demo_relay`。`resolve(context, options)` 接收选人者、合法目标条件和接力效果，由传入的选人者发起原生选目标事件。等待选择返回，再核对选人者和接棒者仍在场、接棒者仍符合条件，随后执行主技能传入的效果。主技能仅在原效果结算后调用一次 `resolve`，并等待本次接力完成。

### 全局规则 · 轮首补给

- **调用时机**　每轮开始时结算补给。
- **判定与结算**　按座次让当前在场且存活的角色各摸一张牌。同一轮只执行一批补给。
- **规则说明**　身份局的前三轮，每轮开始时，存活角色各摸一张牌。
- **启用条件**　仅在身份局开局启用。**对象范围**　当前对局内存活且在场的角色。**结束条件**　第三轮结束后停用，对局结束清理。

由扩展初始化显式调用 `install()`，以带包前缀的 ID 注册规则。1.11.6 可在对局中用 `get.mode() === "identity"` 判断模式，在 `roundStart` 按当前轮号结算。若一次处理全体，可用 `trigger.player = "roundStart"` 将整批处理绑定到轮首事件的角色。按当前对局轮次限制补给，并核对重复监听与本轮重复结算。需要动态卸载时，另查对局结束与重新开局的入口。

## 持有、状态与全局生命周期

- **技能类型与技能调用的共用规则**：能否使用按当前操作者实际持有的有效技能及已确认条件判断，不把原始武将 ID、角色名称或“原拥有者”当作权限。夺取、授予、临时获得技能的调用者遵循同样规则；通过当前引擎的技能有效性和事件流程处理失效。
- **角色状态**：计数、标记、次数与临时效果按实际角色保存，区分不同技能/来源，不能藏在机制单例里让多人共用。逐项确认技能失效、失去、被夺取与重新获得时，哪些状态停止生效、清理、转移、保留或重置，何时恢复；不擅自用“重获”刷新次数，也不让旧监听继续替原角色结算。
- **共用规则的调用契约**：确认谁发起、传入哪个玩家/事件/目标、选择与取消如何返回、效果执行顺序，以及无合法目标或失败时如何结束。避免包装后重复执行原技能或跳过其代价、次数与取消分支。
- **全局规则**：确认启用与停用条件、适用模式/玩家/阶段、重复来源是否叠加，以及再次开局时的重置。`install()` 防止重复注册和重复监听；只有安装成功才记录成功，失败可诊断并清理部分结果。多个持有者或来源共同维持规则时，按确认语义管理来源，不能由一个来源退出就误卸其他来源仍需的规则。
- **联机**：涉及联机适配时，读[自定义机制联机实现示例](custom-mechanic-online.md)。按实际引擎核对玩家选择回传、单次结算，以及相关状态在客机和重连后的表现。

## 读写与交付检查

使用现有 `noname_read_extension`、`noname_write_extension`、`noname_validate`，按实际归属传 `file`；机制定义、直接调用者和初始化接入分别核对。新增定义与必要挂载仍遵守原有区块/精确修改和范围保护，不绕过校验，不新增工具名。

对照已确认清单检查：公开方法确有规则实现，调用方实际使用其返回值或等待结果，传统/模块入口可达；技能被他人获得后可按规则使用，失效与失去后不再错误结算，重获状态正确；多人状态隔离，全局重复来源、停用与再次开局符合规则。涉及联机或词条显示时检查各端表现。交付只登记本轮实际实现的任务节点，区分源码、静态校验与游戏实测；无需为无素材需求的机制补图。
