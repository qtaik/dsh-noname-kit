# 自建势力参考

## 从注册到武将归属

新势力需要统一内部 ID、显示名、势力图及武将归属。已有扩展中的做法是提前注册势力，再让武将引用该 ID。旧扩展可能还依赖全局注册、全局技能或界面补丁才能被模式和 UI 识别，先核对现有有效实现；不能仅因当前引擎提供原生接口，就删除或替换已有兼容方案。

1. **确定 ID 与名称**：内部 ID 遵守任务前缀并检查已有注册，名称使用用户给出的显示名。简称与完整名称按实际界面安排，避免擅自截断有意义的名字。同名或同 ID 先核对归属；复用目标包自己的注册，不覆盖其他包或官方势力。
2. **复制标识图**：用 noname_copy_images 单独复制到扩展的 image/，保留真实后缀，使用独立文件名；不带 taskId，不混入武将静态立绘的复制批次。按工具实际返回路径引用，不把本机绝对路径写入交付代码。
3. **提前注册**：先核对目标引擎的 game.addGroup 定义及关联钩子，在武将和选将界面需要势力之前完成注册，常见位置是扩展 precontent。当前已读实现接受 game.addGroup(id, shortName, fullName, config, type)，默认 type 为 default；config 要传对象，图片通过 image 字段提供，配色可用 color 的六位十六进制颜色。无须因为参考包传了 color 就认定每个引擎都强制要求颜色。
4. **关联武将**：武将对象的 group，或旧数组定义的第二项，填写同一个势力内部 ID。仅填中文名称、只改翻译或复制一张图片，都不等于已经注册并关联势力。

下面是调用形态示意，参数要替换成任务值，并先核对当前引擎，不能原样粘贴占位符：

```js
game.addGroup(groupId, shortName, fullName, {
  color: "#6688AA",
  image: "ext:<扩展文件夹>/image/<势力图片文件名>",
});
```

此例颜色仅是显示示例，不添加玩法效果。当前已读注册流程会登记 lib.group、lib.translate[id]、lib.translate[id + "2"]，并把 config.image 登记为 lib.card["group_" + id].image；卡牌图片读取支持 ext: 前缀。相应 group_ID 翻译用于势力选择卡牌，必要时按实际显示补充。势力色由注册钩子处理，不把参考里的固定 thunder 样式当作所有势力必需配置。钩子可能延迟到加载阶段执行，验证应在相应初始化完成后进行。

## 固定势力与选势力不是一回事

在当前已读引擎中，默认注册会加入 lib.group；select/all 类型还会加入 lib.selectGroup。后者标识可触发开局选势力的原始势力，不是“允许出现在选择列表”的通用开关。get.selectGroup 会从候选中排除 lib.selectGroup 中的势力，部分模式还会重选或随机分配这类武将的势力。因此普通固定新势力沿用默认类型；只有用户需求确实包括开局选择时，才核对目标模式的候选生成、结果处理和各端同步。

## 图片及兼容处理

- 参考扩展通过克隆选择卡并设置 backgroundImage 显示势力图；用户反馈，当时按原生方式似乎未被旧环境识别，因此采用了这套全局方案。已读引擎提供 config.image 入口，但接口存在不代表目标旧模式或 UI 会读取它。先沿注册、候选生成、确认结果及最终武将归属核对实际链路，结合用户反馈保留可用方案；武将框、收藏页、选将页的图片入口也可能不同。当前官方源码的能力不能当成所有旧环境已兼容的证明。
- 原生方式适用时使用原生入口；链路存在缺口时，可以保留、复用或适配必要的全局注册、全局技能和界面钩子，包括为旧式势力选择补齐候选、承接确认结果及应用势力。全局机制本身不是错误，不把“优先原生”变成强制重写或禁止兼容补丁；也不能未经核实把一个包的全局补丁用于所有环境。
- 兼容补丁限定实际需要的模式、事件或界面；包装已有回调时保留原调用及返回值，不重复包装、不污染其他弹窗或玩家。使用 MutationObserver 或全局监听时按其实际生命周期去重和清理，扩展存续期需要的监听可持续保留，不必每次关弹窗都卸掉。用全局技能承接势力选择结果属于兼容实现，不等于新增玩法。核对本地玩家、AI 和各联机端的目标及结果，不把 game.me 的单机处理套给所有玩家。
- 初始化要能重复进入而不重复注册。注册失败应保留可诊断错误，不在尝试前标记成功并吞掉异常；也不为兜底向官方资源目录写图片。已有注册可按归属补缺项，避免覆盖无关配置。
- 参考包中承载资源条、修炼等玩法的全局技能或专用卡牌属于另外的玩法，仅在用户明确需要时实现。

## 验证

按本次涉及的界面检查势力名、标识图和颜色，以及目标武将开局后的实际 group；确认其他势力不受影响，重复加载不重复注册，图片缺失时仍可正常显示文字和操作。涉及联机时，各端都要具有注册代码和素材，并核对选择结果一致。复制成功、注册代码完成和游戏内显示通过分别报告；参考代码不代表所有引擎、模式和 UI 已验证兼容。
