# 视频动态立绘参考

## 基本做法

在原有头像节点内叠加一个静音循环的 video，保留静态立绘作为底图。这是场上武将头像的实现思路；选将框、收藏页或定制 UI 的展示节点要分别按当前源码确认。优先复用目标包已有的播放管理器，只补本次目标武将需要的映射和挂载。

1. **素材与地址**：用 noname_copy_videos 复制素材，按返回的 video/ 相对路径引用。常见地址为 lib.assetURL + "extension/<包名>/video/<文件名>"，使用前核对当前引擎的路径约定；不把本机绝对路径写入交付代码。已有包的旧路径可保留兼容，新视频无须另放 image/。
2. **绑定头像**：建立“武将 ID、头像槽位、视频路径”的对应关系。常见主头像是 player.node.avatar，副将需核对 player.node.avatar2 及其对应身份；不要用 name2 的视频覆盖主将。遇到未明置武将时尊重原界面可见性，不能提前暴露身份。
3. **叠加播放**：创建 video 子节点，设置 muted、loop、autoplay、playsInline；绝对定位铺满头像，object-fit:cover、pointer-events:none。必要时为头像提供相对定位，保留原样式以便恢复。视频初始透明，确认当前绑定仍有效且实际进入播放后再显示，原静态 img/背景保持原状。
4. **更新挂载**：先找当前引擎和 UI 的初始化、换将及节点替换入口，按需更新；不确定时可用有生命周期的低频检查兜底。参考包采用 content 初始化、每 1500ms 扫 game.players；这个间隔不是引擎要求，也不能直接照搬成永久定时器。已有视频的武将、槽位或路径变化时先销毁再挂载，不能仅因节点存在就跳过。
5. **失败回退**：处理资源 error、play() 拒绝及长时间未进入播放。失败时撤掉视频，让静态图继续显示；切换候选路径前先隐藏旧画面。对播放权限或临时加载失败采用有限重试，不永久拉黑路径，也不每次扫描都无限 play()。补入素材、换资源或用户明确重试后允许重新加载。
6. **清理**：换将、节点移除、关闭动效或离开对应界面时统一清理：先使旧绑定失效，再解绑事件、取消超时、pause()、移除 src/source、调用 load() 释放媒体并移除节点。停止不再需要的定时器或观察器，恢复本模块改过的样式；迟到的播放回调不能重新显示旧视频。只是从 DOM 移除或遇禁用开关直接 return 都不够。

## 适配范围

- 常见开关 lib.config.forbid_videoAnimation、回放标记 _status.video 只能作为当前源码核对线索。需要跳过时也要清理已挂载视频，是否支持回放依目标环境处理。
- 头像循环属于各客户端本地呈现，不改变对局结算，也不借用全屏技能特效的 game.pause()/game.resume()。联机时每端都需要对应素材与挂载代码；主机能播放不代表客机已具备资源。
- 新增管理器、样式名和状态使用本扩展命名空间。编辑已有包只处理目标武将和必要挂载；条目与初始化可在不同文件，先定位各自归属再写入。

## 验证与说明

按任务涉及的范围验证：正常播放与点击、视频缺失或不支持时的静态回退、换将后不残留旧视频、双将不串位、禁用和离场后停止、再次进入只挂一个实例。涉及联机时分别观察主机与客机。工具复制成功、代码校验通过和游戏内播放通过分别报告；这份参考本身不构成任何引擎、编码或 UI 的兼容性证明。
